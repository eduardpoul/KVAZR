# Базовые возможности по типам устройств

Что приложение может показать и крутить **без вендорского реверса** — только
стандартные API Windows и классовые протоколы, общие для целых семейств железа.
Это документ для дизайна: каждая строка ниже — кандидат в контрол на странице
устройства.

Каждый пункт помечен источником и проверкой:

- ✅ — проверено пробником на реальном столе (`kvazr --audio`, `--xinput`,
  `--hidpp`, `--system`); вывод пробников — в комментариях к коммитам.
- ▫ — API документирован, на этом столе нет устройства для проверки.
- ✖ — базовым путём **недоступно**; написано явно, чтобы дизайн не рисовал
  контрол, под которым ничего нет. Рядом — какой путь это открыл бы.

Четыре источника данных, по убыванию простоты:

| Источник | Что это | Покрытие |
|---|---|---|
| **Система** (tier 0) | Дерево устройств Windows: имя, класс, подключение, BT-заряд | всё, что воткнуто |
| **Core Audio** | Эндпоинты звука: громкость, mute, пик-метр | любой звук: USB, BT, донглы |
| **XInput** | Геймпады Xbox-протокола: оси, кнопки, вибрация, заряд | всё, что притворяется Xbox-падом |
| **HID++ / VIA** | Классовые протоколы Logitech / QMK-клавиатур | их семейства целиком |

## Гарнитуры и наушники

| Возможность | Чтение | Запись | Источник | Статус |
|---|---|---|---|---|
| Заряд (по Bluetooth) | ✅ | — | система, BT-свойство | ✅ Maxwell BT 95–96% |
| Заряд (по донглу/кабелю) | ✖ | — | только вендорский протокол | ✖ базово нет — RACE у Audeze это и даёт |
| Громкость воспроизведения (Windows-уровень) | ✅ | ✅ | Core Audio | ✅ Maxwell Game 35% / Chat 42% |
| Mute воспроизведения | ✅ | ✅ | Core Audio | ✅ |
| Живой уровень (пик-метр) | ✅ | — | Core Audio | ✅ |
| Громкость/mute встроенного микрофона | ✅ | ✅ | Core Audio (capture-эндпоинт) | ✅ Chat-микрофон Maxwell 50% |
| Несколько эндпоинтов одного устройства (Game/Chat) | ✅ | ✅ | Core Audio, связь по ContainerId | ✅ у Maxwell их три |
| Кодек BT (AAC/SBC/aptX) | ✖ | — | не выставляется публичным API | ✖ (артборд 11b рисует кодек — честно только для устройств с вендорским путём) |
| Заряд AirPods | ✖ | — | Apple BLE-реклама, проприетарно | ✖ базово; отдельная задача, если вообще браться |
| Громкость на самом устройстве (аппаратная) | ✖ | ✖ | вендорский протокол | ✖ — у Audeze это RACE («Общая громкость 0–255») |

**Дизайну:** страница «звукового» устройства без вендорского драйвера — это
громкость/mute per-эндпоинт (их может быть несколько, с именами Game/Chat),
живой пик-метр и, для BT, заряд. Это уже полезная страница.

## Колонки

Как «воспроизведение» у гарнитур: громкость/mute/пик (Core Audio) ✅, заряд по
BT ✅ ▫. Аппаратные эффекты — вендорские ✖.

## Приёмники/донглы/доки

Сами по себе — только строка-факт (уже так). Всё интересное — про устройство
за ними, и оно уже сливается в его строку (каталог: `dongle`/`dock`).

## Что это значит для дизайна — сводка

Новые **классовые** контролы, под которыми уже есть код или прямой API:

1. **Звук-страница (гарнитуры/микрофоны/колонки):** громкость + mute на каждый
   эндпоинт устройства (их бывает несколько, с именами), живой пик-метр входа.
   Всё двустороннее, применяется мгновенно, без «Применить».
2. **Мышь/клава Logitech:** заряд с молнией (уже в строке), дальше того же
   драйвера — DPI и частота опроса.
3. **Геймпад:** вибротест-кнопка, «подключён как Xbox-контроллер», опционально
   живая диагностика стиков.
4. **BT-устройства:** заряд там, где Windows его знает (уже в строке).

Честные дыры, которые дизайну **не рисовать** в базовом наборе: заряд через
2.4G-донгл (кроме Logitech), кодек BT, аппаратные настройки (DPI не-Logitech,
паттерн микрофона, подсветка, ремап) — это всё «список Audeze-уровня», ждём его
от пользователя отдельно.
