# Logitech HID++ — что мышь отдаёт и что у неё можно менять

Замер 25 августа 2026 на Logitech G Pro X Superlight 2 — через приёмник
(`046D:C54D`) и по кабелю (`046D:C09B`), результат одинаковый. Всё прочитано
командами, ничего не записано.

```
dotnet run --project src/Maxwell.Cli -- --hidpp          # имя, заряд, таблица, разрешение
dotnet run --project src/Maxwell.Cli -- --hidpp --deep   # плюс первый вопрос каждой возможности
```

## Почему это не заточка под одну мышь

HID++ 2.0 **самоописывающийся**. У устройства есть таблица возможностей, и сам
перечень — тоже возможность: мышь можно **спросить**, что она умеет, а не
перебирать наугад. Драйвер не знает про Superlight 2 — он читает таблицу и
объявляет строки по тому, что в ней есть.

Поэтому одна реализация покрывает всю линейку Logitech, включая модели, которых
ещё нет. Разница между поколениями — в номерах возможностей: у старых мышей
разрешение `0x2201`, у новых `0x2202`; частота опроса `0x8060` против `0x8061`.
Драйвер должен уметь обе пары и брать ту, что объявлена.

## Что читается

Проверено на живой мыши, ответы приведены как есть.

| возможность | ответ | что это |
|---|---|---|
| `0x0005` | `07 …` | имя («PRO X 2») и тип (мышь) |
| `0x1004` | `0F 0F 02` | заряд и признак зарядки |
| `0x0003` | `02 2121B490 000C 40A9C09B…` | 2 прошивочных блока, **unit id `2121B490`**, транспорт, model id |
| `0x8100` | `01 07 01 05 01 **05** 10 00FF 0A 04` | 5 профилей, формат 7, и **пять кнопок** |
| `0x8110` | `05` | те же пять |
| `0x2202` | см. ниже | разрешение целиком |
| `0x8061` | `00 0F 00` | битовая маска поддерживаемых частот — четыре |

**Разрешение, `0x2202`, по функциям:**

```
fn 0  01                              один сенсор
fn 1  00 050F                         его возможности
fn 2  00 00 0064 E001 00C8 E002 01…   диапазон: от 100 шагом 1 до 200, дальше шагом 2
fn 3  00 00 0320 04B0 0640 0960 0C80  пресеты: 800, 1200, 1600, 2400, 3200
fn 4  00 02 02 02 02 02               список высот отрыва
fn 5  00 0320 0320 0320 0320 02       текущее 800, по умолчанию 800, LOD 2
```

**Два вывода, которые стоят отдельно.**

**Настоящее число кнопок.** `0x8100` отдаёт `buttonCount = 5`, и `0x8110`
подтверждает. Дескриптор HID у этой мыши объявляет шестнадцать, и Windows
повторяет шестнадцать (см. `docs/MICE.md`). То есть у Logitech — и только у неё —
число кнопок вообще узнаваемо.

**Серийный номер.** `unit id` из `0x0003` — единственный способ различить две
одинаковые мыши. Ни дескриптор, ни Windows его не дают.

## Частота опроса

Две половины из двух источников, и только одна из них — знание, хранимое у нас.

**Какие частоты вообще бывают** — это словарь протокола: семь штук, от 8 мс до
125 мкс, в фиксированном порядке битов. Это справочник, а не ответ устройства.

**Какие из семи предлагает эта мышь** — ответ устройства, и он разный по линкам:

```
маска, линк 0   0x000F   →  125, 250, 500, 1000 Гц
маска, линк 1   0x007F   →  125 … 8000 Гц
текущая         03       →  1 мс = 1000 Гц
```

Номера функций взяты не из памяти: чтение — функция 2, запись — 3, по
[реализации Solaar](https://github.com/pwr-Solaar/Solaar). До того я дошёл
измерением до функции 1 и остановился — там, где у разрешения страховкой был
нижний край диапазона (ноль вне его), здесь такой страховки нет: индекс 0 вполне
может оказаться допустимой частотой, и промах на единицу поменял бы человеку
настройку. Прочитать описание оказалось дешевле, чем угадывать на чужой мыши.

Какой из двух списков показывать — не спрашивается, а выводится: устройство
отвечает одну и ту же текущую частоту, каким бы линком его ни спросили, поэтому
верным считается тот список, в котором эта частота есть.

## Что меняется

| | как |
|---|---|
| **разрешение** | `0x2202` fn 6, значения из fn 3 или любое из диапазона fn 2 |
| **частота опроса** | `0x8061`, из маски fn 0 |
| **профили** | `0x8100` — пять профилей, свой формат памяти; отдельная работа |
| высота отрыва | в тех же параметрах, что и разрешение |

## Границы, установленные измерением

- **Функции-записи не вызывались ни разу.** Обход спрашивает только функцию 0 —
  она во всех возможностях HID++ является запросом, а всё, что меняет, лежит
  дальше по списку. Для `0x2202` дошли до fn 5 пошагово: каждый следующий вопрос
  задавался после того, как предыдущий ответил ровно так, как предсказывала
  раскладка.
- **Половина возможностей молчит.** `0x1801`, `0x1802`, `0x1830`, `0x1861`,
  `0x18A1` и прочие отвечают «не реализовано» на функцию 0 — это уведомления и
  сервисные вещи, у которых первой функции нет.
- **`0x1D4B`** отвечает ошибкой: тоже только уведомления.

## Что делать в первую очередь

Разрешение. Оно читается целиком — текущее, по умолчанию, пресеты, диапазон, —
пишется одной функцией, и это то, за чем к мыши приходят. Ляжет в существующую
машинерию строк: диапазон 100…N с пресетами как засечками, ровно как громкость
у гарнитуры.

Следом — паспортные строки, которые уже читаются и стоят одного запроса:
серийный номер и настоящее число кнопок.
