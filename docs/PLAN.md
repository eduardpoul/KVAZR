# KVAZR — план работ

Реализация десктопного приложения для наушников Audeze Maxwell на Avalonia.
Дизайн: `Design/audeze-maxwell/project/Maxwell Hub.dc.html` (11 экранов, Turn 4).
Функциональная спецификация: `docs/FEATURES.md`.

---

## 1. Стек и версии

| Компонент | Версия | Обоснование |
|---|---|---|
| .NET | 10 | Уже стоит, `Kvazr.Race` на нём собран |
| Avalonia | **12.1.1** | Текущая стабильная |
| FluentAvaloniaUI | **3.0.2** | Требует Avalonia 12+, совпало идеально |
| xUnit | последняя | Тесты на RACE-кодек |

Проверено на NuGet: связка Avalonia 12.1.1 + FluentAvaloniaUI 3.0.2 актуальна и совместима. Версии фиксируем через Central Package Management.

Без WebView. Ожидаемый расход в простое — 40–80 МБ против 150–250 МБ у Blazor Hybrid.

## 2. Структура решения

```
Kvazr.App.sln
├─ src/
│  ├─ Kvazr.Race/            HID + RACE протокол           [есть, дорабатывается]
│  │   ├─ Abstractions/          IHidTransport, IHidDeviceWatcher
│  │   ├─ Windows/               hid.dll + setupapi (готовый код)
│  │   ├─ Linux/                 /dev/hidraw                 [фаза 6]
│  │   └─ MacOS/                 IOKit HID Manager           [фаза 6]
│  │
│  ├─ Kvazr.Core/            домен и сервисы               [новый]
│  │   ├─ Model/                 DeviceState, Feature, Profile
│  │   ├─ Services/              IDeviceService, PollingService
│  │   ├─ Notifications/         правила порогов заряда
│  │   └─ Abstractions/          INotifier, IAutostart, IHotkeys, ISettingsStore
│  │
│  ├─ Kvazr.App/             Avalonia UI                   [новый]
│  │   ├─ Themes/                токены дизайна, light/dark
│  │   ├─ Views/                 11 экранов
│  │   ├─ ViewModels/
│  │   ├─ Controls/              BatteryRing, EqCurve, SegmentedControl
│  │   └─ Platform/              Windows: тосты, автозапуск, хоткеи
│  │
│  └─ Kvazr.Cli/             диагностический харнесс       [есть, оставляем]
│
└─ tests/
   └─ Kvazr.Race.Tests/      кодек, парсер пакетов, framing
```

Правило зависимостей: `App → Core → Race`. Обратных ссылок нет. `Core` не знает ни про Avalonia, ни про Windows.

## 5. Фазы

### Фаза 0 — Фундамент
- `Directory.Build.props`: nullable, analyzers, `TreatWarningsAsErrors`, единый `LangVersion`
- `Directory.Packages.props`: Central Package Management
- `.editorconfig`, `.gitignore`
- Реструктуризация под схему из раздела 2, инициализация git

**Готово когда:** решение собирается, `dotnet build` без предупреждений.

### Фаза 1 — Ядро устройства
Текущий `RaceSession` синхронный, Windows-only и без абстракций. Приводим в порядок.

- `IHidTransport`: `OpenAsync`, `WriteAsync`, `ReadInputReportAsync`, `Dispose`
- Windows-реализация из готового кода
- Перевод RACE-слоя на async с `CancellationToken`
- `IHidDeviceWatcher` — детект подключения через `WM_DEVICECHANGE`
- **Юнит-тесты на кодек**: сборка пакета, `ParsePackets`, флаг свежести, staleness. Это чистые функции, покрываем на реальных байтах из логов

**Готово когда:** тесты зелёные, консоль работает как раньше, чтение асинхронное.

### Фаза 2 — Домен и сервисы
- `DeviceState` — иммутабельная запись всех параметров
- `IDeviceService` — **единственный владелец устройства**, сериализует доступ. Компоненты UI к HID не обращаются никогда
- `PollingService : BackgroundService` — заряд раз в 30 с, остальное по требованию
- Запись с валидацией: gain ≤ 150, отсечка `0x88` и `0x8E`, ChatMix 0–20, сайдтон ≤ прочитанного максимума
- Правила уведомлений: пороги 30 / 15 / 5 **с гистерезисом**, взвод флага только при пересечении сверху вниз, сброс при зарядке или возврате выше порога с запасом
- Состояния приложения: `Active` (кабель) / `MonitorOnly` (донгл) / `NotFound`

**Готово когда:** консольный харнесс работает через `IDeviceService`, поллинг не течёт, тесты на правила порогов зелёные.

### Фаза 3 — Оболочка
- Avalonia + FluentAvaloniaUI, DI через `Microsoft.Extensions.Hosting`
- Токены дизайна в ресурсы, светлая тема
- Кастомный заголовок окна (в макете свой chrome: свернуть / развернуть / закрыть с красным ховером `#C42B1C`)
- Двухуровневая навигация
- `TrayIcon` — встроенный в Avalonia, работает на всех трёх платформах
- Окно скрывается в трей, а не закрывается

**Готово когда:** приложение запускается в трей, окно открывается, навигация переключает пустые заглушки.

### Фаза 4 — Экраны
Порядок по ценности, а не по алфавиту:

1. **4b Обзор** — главный экран, сразу даёт пользу
2. **4k / 4j** — пустое состояние и «только донгл». Ранняя реализация, потому что они определяют поведение всего UI при отсутствии устройства
3. **4c Звук** — пресеты, громкость, баланс. График АЧХ — кастомный контрол
4. **4d Микрофон** — шумодав, сайдтон
5. **4e Система**
6. **4a Список устройств**
7. **4i Параметры**
8. **4h Горячие клавиши**
9. **4g Профили**
10. **4f Дополнительно** — последним, потому что содержит опасные операции

Кастомные контролы: `BatteryRing`, `EqCurve` (столбики АЧХ), `SegmentedControl` (шумодав, тема), слайдер с центральной засечкой для баланса.

**Готово когда:** каждый экран совпадает с макетом и работает на живом устройстве.

### Фаза 5 — Интеграция с системой (Windows)
- Иконка в трее с **процентом, отрисованным динамически**
- `INotifier` → `AppNotificationBuilder`, тосты о заряде и завершении зарядки
- `IAutostart` → ключ в `HKCU\...\Run`, опция «свёрнутым»
- `IHotkeys` → `RegisterHotKey`, 5 сочетаний из макета
- Попап при подключении устройства

**Готово когда:** всё работает после перезагрузки, хоткеи ловятся при свёрнутом окне.

### Фаза 6 — Кроссплатформенность
- Linux: `/dev/hidraw` + **udev-правило для VID `0x3329`** в установщик. Без правила доступ без root закрыт, и это выглядит как «приложение не видит наушники»
- macOS: IOKit HID Manager
- `INotifier`: D-Bus `org.freedesktop.Notifications` для Linux, `UNUserNotificationCenter` для macOS
- Автозапуск: `.desktop` в autostart для Linux, `LaunchAgent` для macOS

**Готово когда:** сборка и запуск на Ubuntu и macOS, чтение заряда работает.

### Фаза 7 — Полировка
- Тёмная тема
- Локализация ru / en
- Публикация: self-contained, trimmed, по возможности NativeAOT

## 7. Пробелы между макетом и реальностью

Здесь макет опережает то, что мы умеем читать. Каждый пункт — задача, а не недочёт дизайна.

**Факт зарядки.** Экран 4b показывает «Заряжается», но флага мы не читаем. Сначала ищем его в нерасшифрованных байтах статусной структуры `0x0910`, и только если не найдём — выводим косвенно по росту заряда.

**Оставшееся время.** Экран 4j показывает «осталось примерно N ч». В макете это `battery/100 × 78`, то есть линейная модель от 78 часов. Приемлемо как первое приближение, но подписывать надо осторожно — «примерно», как в макете и сделано.

**Таймер автовыключения.** Устройство отдаёт `7`, макет показывает «30 минут». Значит `7` — индекс в списке пресетов, и соответствие надо составить: перебрать значения через Audeze HQ и сверить. До этого список в UI не наполнять.

**Список устройств.** Экран 4a показывает «Подключены 2», а 4b — одно устройство с двумя транспортами (кабель и донгл строками внутри). Надо определиться с моделью: одни наушники, доступные по двум каналам, или два отдельных устройства. Я склоняюсь к первому — это соответствует реальности и экрану 4b. Требует уточнения.

**Мок-значения.** В макете шумодав «Высокое» и сайдтон включён на 18, у реального устройства — выкл и 9. Это просто демо-данные, ориентируемся на живые.

## 8. Правила разработки

- DI везде, `Microsoft.Extensions.Hosting` как композиционный корень
- Настройки — options pattern с `IOptionsMonitor`, хранение в `%AppData%`
- `ILogger` во всех сервисах, файловый лог с ротацией
- `CancellationToken` во всех async-путях, никаких `async void` кроме обработчиков событий
- MVVM: вьюмодели без ссылок на Avalonia-контролы, `CommunityToolkit.Mvvm` для генерации
- Никаких обращений к HID из UI-потока и из компонентов — только через `IDeviceService`
- Тесты обязательны на: кодек RACE, правила порогов заряда, валидацию записи

## 9. Риски

| Риск | Оценка | Что делаем |
|---|---|---|
| **Тёмная тема расходится с задумкой** | Средний | Финальные экраны в макете только светлые. Вывести палитру самим и показать на утверждение до того, как разойдётся по 11 экранам |
| **Avalonia TrayIcon на Linux** | Средний | Подтверждён на Ubuntu, на других DE не гарантирован. Проверять рано, в фазе 6, а не в конце |
| Точность переноса макета | Низкий | Токены извлечены из исходника, размеры заданы явно |
| Регрессии в RACE-слое | Низкий | Покрываем тестами в фазе 1, до всякого UI |
| Опасные команды | **Устранён** | `factoryReset` и `pairing` уже в чёрном списке в коде |

## 10. Порядок

Первые три фазы дают работающее приложение в трее с реальным зарядом — это самая ценная часть, и она не зависит от дизайна. Экраны накладываются поверх готового ядра.

Начинать предлагаю с фазы 0 и 1: реструктуризация плюс тесты на кодек. Скучно, но именно это не даст развалиться на фазе 4, когда 11 экранов начнут одновременно дёргать устройство.
