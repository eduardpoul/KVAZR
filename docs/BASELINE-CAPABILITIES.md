# Дизайн-бриф: возможности по всем категориям устройств

Что рисовать на странице каждого типа устройства. Разделено на два уровня:

- **Базовый** — доступно на **любом** устройстве этого класса, без вендорского
  реверса, только стандартными API и классовыми протоколами. Это страница «по
  умолчанию» для класса.
- **Расширенный** — наши **особые** устройства, где вскрыт вендорский протокол
  и возможностей кратно больше. Каждое такое — отдельная реализация; список
  растёт.

Всё ниже проверено на реальном железе (пробники `maxwell --desk/--audio/
--xinput/--hidpp`), кроме помеченного ▫ (документировано, ждёт устройства) и
🔒 (за вендорским реверсом — план).

## Как читать: контрол = примитив

Дизайн уже оперирует 12 примитивами (артборд 2a). Каждая возможность ниже
привязана к одному из них — рисуй соответствующий контрол:

| Примитив | Контрол | Пример |
|---|---|---|
| **Readout** | значение только на чтение | «Заряд 95%» |
| **Toggle** | переключатель | «Шумоподавление вкл» |
| **Range** | слайдер + значение | «Громкость 0–100» |
| **RangeGroup** | несколько слайдеров вместе | «Баланс L/R» |
| **Choice** | дропдаун или сегменты | «Частота 125…1000 Гц» |
| **Action** | кнопка (с подтверждением, если опасно) | «Вибротест», «Сброс» |
| **Curve** | редактор кривой | «Эквалайзер», «Кривая отклика» |
| **KeyMap** | раскладка со слоями | «Клавиши» |
| **ButtonMap** | список кнопка→действие | «Назначение кнопок» |
| **Lighting** | зоны + палитра | «Подсветка» |
| **ProfileSet** | слоты профилей | «Профили в памяти» |
| **HostSlots** | слоты хостов | «Хост 1/2/3» |

Статусы: **Ч** читается, **З** пишется (двусторонний контрол), 🟡 первая запись
помечается янтарём (Untested), пока живьём не подтверждена.

# ГАРНИТУРЫ И НАУШНИКИ

## Базовая страница (любая гарнитура/наушники)

| Возможность | Примитив | Ч/З | Источник |
|---|---|---|---|
| Заряд (по Bluetooth) | Readout | Ч | система |
| Громкость воспроизведения | Range | Ч/З | Core Audio |
| Mute воспроизведения | Toggle | Ч/З | Core Audio |
| Живой уровень (пик-метр) | Readout (анимир.) | Ч | Core Audio |
| Громкость встроенного микрофона | Range | Ч/З | Core Audio |
| Mute микрофона | Toggle | Ч/З | Core Audio |
| Несколько аудиовыходов (Game/Chat) | по строке на выход | Ч/З | Core Audio по ContainerId |

**Что это за экран:** несколько именованных строк громкости (у устройства
может быть 2–3 выхода — Game, Chat, — и микрофон), у каждой слайдер + mute,
сверху живая полоска уровня. Уже полезно, ничего вендорского.

**Нельзя базово:** заряд по донглу/кабелю, кодек BT, аппаратная громкость на
устройстве, эффекты — только у особых (ниже).

# МЫШИ

## Базовая страница

Мышь **Logitech** (за ресивером или на кабеле) — фактически «класс», один
протокол HID++ на всю линейку:

| Возможность | Примитив | Ч/З | Статус |
|---|---|---|---|
| Заряд + зарядка (молния) | Readout | Ч | ✅ готово |
| Имя и модель | Readout | Ч | ✅ готово |
| Прошивка | Readout | Ч | ✅ читается |

Мыши **других вендоров** (Razer, Glorious…) — только tier-0: имя, класс,
подключение. DPI/подсветка у них за своими протоколами (не класс).

## Расширенная — Logitech (тот же драйвер, очередь реализации)

Superlight 2 отдала полную таблицу — это доступно всем мышам Logitech:

| Возможность | Примитив | Ч/З | Статус |
|---|---|---|---|
| DPI: ступени, текущая, X/Y | Range/Choice | Ч/З | ▫ фича 0x2202 |
| Частота опроса (125 Гц…8 кГц) | Choice | Ч/З | ▫ фича 0x8061 |
| **Профили в памяти мыши** | ProfileSet | Ч/З | ▫ фича 0x8100 — как артборд 9c |
| Назначение кнопок | ButtonMap | Ч/З | ▫ фича 0x1b04 |
| Режим питания (perf/endurance) | Toggle | Ч/З | ▫ фича 0x8090 |
| Высота отрыва (lift-off) | Choice | Ч/З | ▫ фича 0x2251 |
| Подсветка RGB (у моделей с RGB) | Lighting | Ч/З | ▫ фича 0x8070 |

**Важно для дизайна:** DPI и профили хранятся **в самой мыши** — «сохранить»
пишет в железо, работает без нашего приложения. Это ProfileSet как у мыши в
артборде 9c: несколько онбордных слотов (DPI + частота + кнопки), переключаемых
кнопкой на мыши.

> Конкретно твоя Superlight 2 — **без RGB** (нет светодиодов), у других
> Logitech с подсветкой строка Lighting появляется автоматически.

# КЛАВИАТУРЫ

## Базовая страница

| Возможность | Примитив | Ч/З | Источник |
|---|---|---|---|
| Заряд по Bluetooth | Readout | Ч | система |
| Заряд Logitech за ресивером | Readout | Ч | HID++ (тот же драйвер) |

Без кабеля/BT — только имя и «USB-донгл». Заряд по 2.4G-донглу базово
недоступен (проверено).

## Расширенная — VIA/QMK-клавиатуры (по кабелю)

Класс-протокол: NuPhy, Keychron, GMMK, почти весь кастом. Всё по кабелю
(через донгл VIA не идёт):

| Возможность | Примитив | Ч/З | Статус |
|---|---|---|---|
| Раскладка со слоями | KeyMap | Ч/З | ▫ VIA |
| Макросы | ButtonMap/спец. | Ч/З | ▫ VIA |
| Подсветка (яркость/эффект/цвет/зоны) | Lighting | Ч/З | ▫ VIA |
| Тестер нажатий (живая матрица) | Readout (визуал) | Ч | ▫ VIA |

**Модель «кабель → снимок → донгл»** (важно нарисовать честно): по кабелю
раскладка читается и правится; на донгле показываем **снимок с датой** в
read-only и строку «подключите кабель, чтобы изменить». Раскладка живёт в
клавиатуре и по донглу всегда применяется — мы просто не можем её менять без
кабеля. Тот же язык, что «обновлено 14:41».

**Рисунок клавиатуры** берётся из MIT-базы определений по VID:PID (как фото
устройств). Нет определения → слои/макросы/свет/тестер всё равно работают, нет
только картинки раскладки.

# ГЕЙМПАДЫ

## Базовая страница (любой XInput-совместимый)

| Возможность | Примитив | Ч/З | Статус |
|---|---|---|---|
| Подключён / тип | Readout | Ч | ✅ XInput |
| Живая диагностика стиков/кнопок | Readout (визуал) | Ч | XInput — «тестер дрейфа» |
| Вибротест (2 мотора) | Action | З | XInput |
| Заряд | Readout | Ч | **только настоящие Xbox wireless**; сторонние донглы врут «проводной» |

**Экран:** «подключён как Xbox-контроллер», кнопка вибротеста, опционально
живой визуал стиков (дрейф). Заряд — не у всех: у не-Xbox падов через донгл
его нет.

**Про лепестки честно:** в XInput их **не существует** — пад отрабатывает их
сам, подменяя кнопками. Обнаружить и назначить лепестки можно **только**
вендорским протоколом (расширенный уровень). Не рисуй «лепестки» в базовой.

# ПРИЁМНИКИ / ДОНГЛЫ / ДОКИ

Отдельной страницы **нет** — сливаются в устройство, которому служат (каталог:
`dongle`/`dock`). На строке устройства — чип «USB-донгл» / «Док». Неопознанный
донгл без устройства — строка-факт (артборд 11c).

# Сводка для дизайна: какие экраны заводить

1. **Аудио-класс** (гарнитуры/микро/колонки): страница из именованных строк
   громкости + mute + живой пик. Один шаблон на три категории.
2. **Мышь-класс** (Logitech): заряд, DPI (Range/Choice), частота (Choice),
   профили (ProfileSet), кнопки (ButtonMap), + Lighting у RGB-моделей.
3. **Клава-класс** (VIA): KeyMap со слоями, макросы, Lighting, тестер;
   read-only-снимок с датой на донгле.
4. **Геймпад-класс** (XInput): статус, вибротест (Action), визуал-диагностика
   стиков; заряд опционально.
5. **Особые устройства** — расширяют свой класс дополнительными строками из
   таблиц выше. Дизайну достаточно рисовать примитивы; какие именно строки
   поднимутся — решает драйвер по факту устройства (пустых контролов не будет).

Каждый «особый» девайс = класс-страница + его личные строки. Растущий список
особых: **Audeze (готово)**, **Switch Pro (готов протокол)**, **Flydigi,
QuadCast RGB, VIA-клавы (в очереди)**, **DualSense (если появится)**.
