# Мыши — что реально отдаёт железо

Замер 25 августа 2026 на этом столе. Всё ниже прочитано командами, ничего не
взято из документации и ничего не написано в устройства.

Воспроизвести:

```
dotnet run --project src/Maxwell.Cli -- --pointers     # дескриптор, кнопки, оси, запись
dotnet run --project src/Maxwell.Cli -- --system       # что знает Windows сама
dotnet run --project src/Maxwell.Cli -- --hidpp        # Logitech: имя, заряд, таблица возможностей
dotnet run --project src/Maxwell.Cli -- --devices      # что из этого складывается в устройство
```

## Три линка — три разных ответа

| | имя | заряд | кнопки/оси | DPI, частота, профили |
|---|---|---|---|---|
| **Bluetooth LE** | да, от Windows | **да, от Windows** | честные, описывают саму мышь | только вендорский протокол, если он есть |
| **USB-донгл** | **нет** — виден приёмник | только вендорский | конверт приёмника, не мышь | вендорский; у Logitech объявлено много |
| **Провод** | да, от Windows | нет и не будет | честные (не измерено, мыши нет) | вендорский |

Главное различие не в количестве данных, а в том, **о ком** они. По кабелю и по
Bluetooth операционная система видит саму мышь. Через приёмник она видит
приёмник и мышевидную коллекцию на нём — и коллекция описывает то, что приёмник
способен передать, а не то, что у мыши есть.

## HP 2.4G wireless and BT Mouse — `03F0:0F4C`, Bluetooth LE

```
link      Bluetooth LE
report    6 bytes in
buttons   5
axis      Y      12 bits  -2048..2047
axis      X      12 bits  -2048..2047
axis      Wheel   8 bits   -127..127
wheel     stepped
write     refused (Win32 5)
also      page 0x000C usage 0x01  in 0  out 0  feature 21  · write allowed
          feature   declared, none answered
```

Коллекций ровно две: мышь и Consumer. **Вендорской страницы нет** — ни одной
коллекции выше `0xFF00`. Значит менять на этой мыши нечего: нет протокола, в
котором было бы что менять.

Запись в мышиную коллекцию Windows **отказывает** — Win32 5, доступ запрещён.
Это не препятствие, которое можно обойти: мышь ведёт курсор, и система держит
её эксклюзивно именно поэтому. Consumer-коллекция открывается на запись, но её
21 байт feature-отчётов не отвечает ни на один идентификатор из семнадцати
опрошенных — объявление есть, за объявлением ничего. Писать туда вслепую я не
стал и не буду: это устройство, которое двигает курсор.

Из GATT-сервисов мышь показывает `1800`, `1801`, `180A` (Device Information),
`180F` (Battery) и `1812` (HID over GATT). Заряд Windows берёт из `180F` и
выкладывает как свойство устройства — читать GATT самим не потребовалось.

**Итог: только чтение.** Имя, заряд, 5 кнопок, две оси ±2048, колесо без
наклона и без высокого разрешения. Для страницы этого хватает на честный
паспорт устройства и на заряд в трее.

## Logitech G Pro X Superlight 2 — через приёмник `046D:C54D`

Дескриптор приёмника:

```
buttons   16
axis      X/Y   16 bits  -32767..32767
axis      Wheel, Horizontal wheel
```

У Superlight 2 пять кнопок. Шестнадцать — это ёмкость приёмника, и по
дескриптору нельзя даже узнать, какая мышь за ним: в списке она называется
«USB Receiver». Всё настоящее приходит по HID++:

```
slot 1  PRO X 2 · Mouse · 87%
        32 features:
          0x0005 device name and kind      0x2202 extended adjustable resolution
          0x1004 unified battery           0x8061 extended report rate
          0x1D4B wireless device status    0x8100 onboard profiles
          0x0003 device information        0x8110, 0x8090, 0x80E0, 0x2250, 0x2251,
                                           0x1500, 0x1801…0x1890, 0x1E00…
```

Список пришёл от самого устройства: в HID++ 2.0 перечень возможностей — сам
возможность, так что мышь можно **спросить**, а не перебирать наугад. Читаем мы
из тридцати двух две: имя с типом и заряд. Разрешение (`0x2202`), частота опроса
(`0x8061`) и профили (`0x8100`) объявлены устройством, и это единственный
известный путь что-то на мыши **менять**.

## NuPhy Air96 V2 Dongle — `19F5:3247`

Мышевидная коллекция на клавиатурном донгле: 8 кнопок, оси ±127, наклон колеса.
Мыши за ним нет — это эмуляция, и она попала в список ровно потому, что список
строится по объявлению.

## Что было починено по дороге

Оба дефекта нашлись, потому что мышь принесли на стол.

**BLE-устройства были безымянными и без заряда.** Опрашивался перечислитель
`BTHLEDEVICE`, а он несёт по узлу на каждый GATT-сервис — мышь приходила как
«Bluetooth LE Service {0000180a-…}» и без батареи, при том что Windows рядом
показывала имя и 100%. Имя и заряд лежат на узле самого устройства, в
перечислителе `BTHLE`. Одна строка.

**BLE-мышь называла свой линк проводом.** HID-узел мыши перечисляется под `HID`,
как всё на кабеле, и определялся как USB — а контейнер при этом держал и её
LE-узлы, так что одно устройство заявляло два разных типа подключения. HID-узел
Bluetooth-устройства отличим: в его идентификаторе стоит сервис HID over GATT,
`{00001812-…}`.

## Не измерено

- **Проводная мышь** — на столе нет. Ожидание: как Bluetooth, но без заряда;
  дескриптор описывает саму мышь.
- **Эта же HP по своему донглу 2.4 ГГц** — мышь двухрежимная. Интересно ровно
  тем, что даст сравнить один и тот же аппарат на двух линках: сколько теряется
  при переходе на приёмник.
- **Чтение `0x2202` / `0x8061` / `0x8100` у Logitech** — объявлены, форма
  документирована, ни один не прочитан.
