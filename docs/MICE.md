# Мыши — что реально отдаёт железо

Замер 25 августа 2026 на этом столе: BLE-мышь, та же Logitech через приёмник и
она же по кабелю. Всё ниже прочитано командами, ничего не взято из документации
и ничего не написано в устройства.

Воспроизвести:

```
dotnet run --project src/Maxwell.Cli -- --pointers     # дескриптор, кнопки, оси, запись
dotnet run --project src/Maxwell.Cli -- --system       # что знает Windows сама
dotnet run --project src/Maxwell.Cli -- --hidpp        # Logitech: имя, заряд, таблица возможностей
dotnet run --project src/Maxwell.Cli -- --devices      # что из этого складывается в устройство
```

## Три линка — три разных ответа

| | имя | заряд | кнопки/оси из дескриптора | DPI, частота, профили |
|---|---|---|---|---|
| **Bluetooth LE** | да, от Windows | **да, от Windows** | совпали с настоящими | только вендорский протокол, если он есть |
| **USB-донгл** | **нет** — виден приёмник | только вендорский | **не совпали** | вендорский; у Logitech объявлено много |
| **Провод** | да, от Windows | **да, вендорский, вместе с «заряжается»** | **не совпали** | вендорский, тот же полный список |

Главное различие — **о ком** данные. По кабелю и по Bluetooth операционная
система видит саму мышь. Через приёмник она видит приёмник: устройство в списке
называется «USB Receiver», и никакого способа узнать из дескриптора, какая мышь
за ним, нет.

Заряд по кабелю есть, и это не опечатка: у беспроводной мыши на проводе есть и
заряд, и признак зарядки — оба по вендорскому протоколу, который по кабелю
доступен напрямую. За три чтения подряд значение шло 87 → 88 → 89 %.

## Чему в дескрипторе нельзя верить

Самый дорогой вывод этого замера, и он получился только потому, что одну и ту же
мышь померили на двух линках.

Через приёмник Superlight 2 объявляет 16 кнопок и оси ±32767. Первое объяснение
было «это ёмкость приёмника, а не мышь» — и оно **неверно**: по кабелю та же
мышь объявляет ровно то же самое. Это её собственный дескриптор, и он описывает
не эту модель, а весь класс: производитель объявляет надмножество и заполняет
столько, сколько есть.

У Superlight 2 пять кнопок. Ни одна команда не может это узнать из дескриптора —
там честно написано шестнадцать. Значит **число кнопок и разрядность осей на
странице показывать нельзя**: это не факт об устройстве, это заголовок протокола.

BLE-мышь, для сравнения, объявила пять кнопок и оси ±2048, и это похоже на
правду. То есть дескриптор не врёт всегда — он врёт там, где производителю
удобнее один дескриптор на линейку. Отличить одно от другого изнутри нельзя.

**И Windows не помогает.** Raw Input — единственное место, где система называет
число кнопок и частоту опроса от своего имени. Спросили:

| | дескриптор | Windows (Raw Input) |
|---|---|---|
| Logitech PRO X 2 | 16 кнопок, есть горизонт. колесо | **16 кнопок**, rate 0, горизонт. колеса **нет** |
| HP BLE | 5 кнопок, нет горизонт. колеса | 5 кнопок, rate 0, нет |

Число кнопок Windows просто повторяет за дескриптором — независимого источника
нет. Частоту опроса не отдаёт вовсе (0 у обеих). Единственное, где её ответ
лучше: горизонтальное колесо — дескриптор Logitech его объявляет, Windows
говорит «нет», и права она: у Superlight 2 колесо не наклоняется.

## HP 2.4G wireless and BT Mouse — `03F0:0F4C`, Bluetooth LE

```
link      Bluetooth LE
report    6 bytes in
buttons   5
axis      Y      12 bits  -2048..2047
axis      X      12 bits  -2048..2047
axis      Wheel   8 bits   -127..127
wheel     stepped
write     refused (Win32 5)
also      page 0x000C usage 0x01  in 0  out 0  feature 21  · write allowed
          feature   declared, none answered
```

Коллекций ровно две: мышь и Consumer. **Вендорской страницы нет** — ни одной
коллекции выше `0xFF00`. Значит менять на этой мыши нечего: нет протокола, в
котором было бы что менять.

Запись в мышиную коллекцию Windows **отказывает** — Win32 5, доступ запрещён.
Это не препятствие, которое можно обойти: мышь ведёт курсор, и система держит
её эксклюзивно именно поэтому. Consumer-коллекция открывается на запись, но её
21 байт feature-отчётов не отвечает ни на один идентификатор из семнадцати
опрошенных — объявление есть, за объявлением ничего. Писать туда вслепую я не
стал и не буду: это устройство, которое двигает курсор.

Из GATT-сервисов мышь показывает `1800`, `1801`, `180A` (Device Information),
`180F` (Battery) и `1812` (HID over GATT). Заряд Windows берёт из `180F` и
выкладывает как свойство устройства — читать GATT самим не потребовалось.

**Итог: только чтение.** Имя, заряд, 5 кнопок, две оси ±2048, колесо без
наклона и без высокого разрешения. Для страницы этого хватает на честный
паспорт устройства и на заряд в трее.

## Logitech G Pro X Superlight 2 — через приёмник `046D:C54D`

Дескриптор — тот же, что и по кабелю (см. выше, верить ему нельзя):

```
buttons   16
axis      X/Y   16 bits  -32767..32767
axis      Wheel, Horizontal wheel
```

По дескриптору нельзя даже узнать, какая мышь за приёмником: в списке она
называется «USB Receiver». Всё настоящее приходит по HID++:

```
slot 1  PRO X 2 · Mouse · 87%
        32 features:
          0x0005 device name and kind      0x2202 extended adjustable resolution
          0x1004 unified battery           0x8061 extended report rate
          0x1D4B wireless device status    0x8100 onboard profiles
          0x0003 device information        0x8110, 0x8090, 0x80E0, 0x2250, 0x2251,
                                           0x1500, 0x1801…0x1890, 0x1E00…
```

Список пришёл от самого устройства: в HID++ 2.0 перечень возможностей — сам
возможность, так что мышь можно **спросить**, а не перебирать наугад. Читаем мы
из тридцати двух две: имя с типом и заряд. Разрешение (`0x2202`), частота опроса
(`0x8061`) и профили (`0x8100`) объявлены устройством, и это единственный
известный путь что-то на мыши **менять**.

## Та же мышь по кабелю — `046D:C09B`

Отдельное устройство с точки зрения USB: другой идентификатор продукта, своё имя.

```
PRO X 2  046D:C09B
    link      USB
    buttons   16   ← тот же неверный дескриптор
    write     refused (Win32 5)
    also      page 0xFF00 usage 0x01  in 7   out 7   · write allowed
    also      page 0xFF00 usage 0x02  in 20  out 20  · write allowed
```

Две коллекции `0xFF00` — это HID++, короткий и длинный отчёты, **на самой мыши**,
и обе открываются на запись. То есть по кабелю вендорский протокол доступен
напрямую, без приёмника:

```
slot 255  PRO X 2 · Mouse · 89% ⚡     (тот же список из 32 возможностей)
```

Приложение это уже умеет: устройство собирается как
`hidpp:c09b:direct`, `usb:046d:c09b`, транспорт USB, заряд и признак зарядки.

Как отличить провод от приёмника: индекс `0xFF`. У приёмника длинный отчёт на нём
молчит, у мыши на кабеле — отвечает, и отвечает на любом индексе, будучи
единственным устройством на шине. Пока это не учитывалось, пробник печатал одну
и ту же мышь шесть раз.

## NuPhy Air96 V2 Dongle — `19F5:3247`

Мышевидная коллекция на клавиатурном донгле: 8 кнопок, оси ±127, наклон колеса.
Мыши за ним нет — это эмуляция, и она попала в список ровно потому, что список
строится по объявлению.

## Что было починено по дороге

Оба дефекта нашлись, потому что мышь принесли на стол.

**BLE-устройства были безымянными и без заряда.** Опрашивался перечислитель
`BTHLEDEVICE`, а он несёт по узлу на каждый GATT-сервис — мышь приходила как
«Bluetooth LE Service {0000180a-…}» и без батареи, при том что Windows рядом
показывала имя и 100%. Имя и заряд лежат на узле самого устройства, в
перечислителе `BTHLE`. Одна строка.

**BLE-мышь называла свой линк проводом.** HID-узел мыши перечисляется под `HID`,
как всё на кабеле, и определялся как USB — а контейнер при этом держал и её
LE-узлы, так что одно устройство заявляло два разных типа подключения. HID-узел
Bluetooth-устройства отличим: в его идентификаторе стоит сервис HID over GATT,
`{00001812-…}`.

## Что из этого следует для страницы мыши

- **Базовый уровень для любой мыши** — имя, класс, линк — есть уже сейчас.
- **Заряд** бесплатен по Bluetooth (от Windows) и по вендорскому протоколу на
  Logitech, по обоим её линкам.
- **Кнопки и оси из дескриптора показывать нельзя.** Они не проверяемы и на
  Logitech заведомо неверны.
- **DPI, частота опроса, профили** — только вендорский протокол, и у Logitech он
  доступен одинаково по кабелю и через приёмник.

## Что показал тестер

`--tester` считает поток Raw Input: ничего не открывает, ничего не пишет, работает
с любой мышью. Первый прогон на двух мышах, 25 секунд.

```
Logitech PRO X 2 (кабель)
    buttons   left, right, middle, fourth (back), fifth (forward)
    wheel     да, шаги ровно -120 и 120
    horizontal wheel — не появилось ни разу

HP 2.4G (Bluetooth LE)
    buttons   left, right, middle, fourth (back), fifth (forward)
    wheel     да, шаги -840 … 720, все кратны 120
    horizontal wheel — не появилось ни разу
```

**Пять кнопок у Superlight, а не шестнадцать.** Дескриптор уличён не рассуждением,
а наблюдением: нажали все, что есть, — их пять. Это и есть ценность тестера.

**Горизонтального колеса нет ни у одной**, хотя дескриптор Logitech его объявляет.
Совпало с ответом Windows — значит права была она, а дескриптор врал и здесь.

**Колесо ступенчатое у обеих.** Ровно 120 на щелчок; у HP приходят кратные — это
несколько щелчков, склеенных в один отчёт, а не высокое разрешение. Высокое
разрешение дало бы шаги *меньше* 120.

Оговорка про потолок остаётся: Raw Input несёт пять кнопок и колесо, шестая
приходит другой коллекцией. Число — «не меньше», а не «ровно».

### Пошаговый прогон

Тестер переписан на последовательный: спрашивает по одному контролу. На
Superlight ответили все семь — левая, правая, клик колеса, обе боковые, колесо
вверх и вниз. Частота при быстром движении вышла **160 в секунду** против 60 при
спокойном; это подтверждает, что величина описывает руку до тех пор, пока рука не
станет быстрее мыши.

Что важнее самого списка: непрошедший шаг теперь читается как «промолчало», а не
как «у мыши этого нет». Мы не знаем, не нажали контрол или он сломан, и говорить
за пользователя не будем.

### Частоту опроса этим способом не измерить, и вот почему

Ушло две попытки, и обе были неверны по-своему.

Сначала считалось среднее по интервалу от первого отчёта до последнего — а в
интервал попадают паузы между движениями, и любая мышь выходила сорока с чем-то.
Потом добавился «кратчайший промежуток между отчётами», и он показал `0.0 ms`:
время бралось в момент, когда наш поток снял сообщение с очереди, а не когда
отчёт пришёл, так что несколько доставленных вместе получали одну метку. Величина
описывала наш насос сообщений и выдавалась за факт о мыши. Убрана.

Осталась одна: **пиковая частота**, самая занятая десятая доля секунды × 10.
Десятая, а не секунда, потому что никто не двигает мышь на пределе целую секунду
— целая усредняет быстрый рывок вместе с замедлением в конце.

Но и это **пол, а не потолок**, и никакая арифметика этого не исправит. Мышь
шлёт отчёт, когда ей есть о чём сообщить. Опрашиваемая тысячу раз в секунду и
двигаемая мягко, она отвечает на малую долю опросов — то есть считается скорость
руки, пока рука не станет быстрее мыши. На втором прогоне вышло 60 в секунду; это
означает «не меньше 60», и ничего больше.

Побочно: внедрённый ввод (`mouse_event`) для этого не годится вовсе — 300
движений подряд дали 11 отчётов, система их склеивает. Канал им проверить можно,
частоту нельзя.

## Что на базовом уровне ещё не выбрано

Одно, и оно единственное существенное: **поток Raw Input**. Всё выше —
объявления; поток — поведение. Он универсален, не требует ни прав, ни открытия
устройства (мышь открыть нельзя — Win32 5), и даёт то, чего не даёт ни один
источник объявлений:

- **настоящее** число кнопок — какие вообще когда-либо срабатывают;
- **настоящую** частоту отчётов — считанную, а не объявленную;
- есть ли на самом деле горизонтальное колесо и высокое разрешение.

Цена: нужны движения пользователя, то есть это страница-тестер, а не строка в
паспорте. Ровно та же форма, что задумана для геймпада.

Мелочь того же уровня: строки USB — производитель и серийный номер
(`HidD_GetManufacturerString`, `HidD_GetSerialNumberString`). Серийник —
единственный способ различить две одинаковые мыши.

## Отклонено: системные настройки указателя

`--pointer` читает то, что Windows держит про указатель: скорость, ускорение,
строки на щелчок колеса, время двойного клика, обмен кнопок. Всё это пишется тем
же вызовом и работает с любой мышью.

**Решено не делать.** Это настройки Windows, а не устройства: на машине один
указатель, сколько бы мышей ни лежало. Панель настроек Windows внутри программы
про устройства — не то, зачем её открывают, и трогают эти ползунки раз в жизнь.
Пробник оставлен, чтобы к вопросу не возвращаться.

## Не измерено

- **Эта же HP по своему донглу 2.4 ГГц** — мышь двухрежимная. Даст сравнить один
  аппарат на трёх линках.
- **Чтение `0x2202` / `0x8061` / `0x8100` у Logitech** — объявлены, форма
  документирована, ни один не прочитан.
- **Мышь другого производителя.** Всё, что известно про вендорский уровень, —
  это Logitech. Razer, Glorious и прочие имеют свои протоколы, и ни один из них
  здесь не видели.
