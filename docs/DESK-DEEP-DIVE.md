# Глубокая разведка устройств этого стола

Что каждое устройство (кроме Audeze — он уже разобран RACE-драйвером) реально
выставляет на шину, и что из этого можно превратить в функции. Всё ниже снято
пробниками `maxwell --desk` / `--airpods` с живого железа; вывод — в истории
коммитов. Разведка строго read-only: в неизвестные вендорские интерфейсы не
записано ни байта.

---

## Logitech G Pro X Superlight 2 — вскрыта полностью

HID++ отдал всю таблицу: **33 фичи**. Значимые для функционала:

| Фича | Что даёт | Статус |
|---|---|---|
| 0x1004 UnifiedBattery | заряд + зарядка | ✅ уже в приложении |
| 0x2202 ExtendedAdjustableDPI | DPI: список ступеней, текущее, **запись** | путь ясен, чтение/запись документированы |
| 0x8061 ExtendedReportRate | частота опроса вплоть до 8 кГц, чтение/**запись** | путь ясен |
| 0x8100 OnboardProfiles | профили в памяти мыши | как у артборда 9c |
| 0x8090 ModeStatus | режим perf/endurance | тумблер |
| 0x2251 LiftDetection | высота отрыва | настройка |
| 0x1d4b WirelessDeviceStatus | события подключения | для мгновенного обновления строки |
| 0x0003 DeviceInfo | версии прошивки | строка «Прошивка» |
| 0x00C3 / 0x00D0 | DFU (обновление прошивки) | не трогаем |
| ~15 фич [hidden]/[eng] | заводские/инженерные | не трогаем принципиально |

Мышь на кабеле отвечает на index 0xFF; за ресивером — на слоте. Один драйвер
покрывает оба пути (уже так и написан).

**Вывод:** страница мыши уровня артборда 9a-9c (DPI, частота, профили,
кнопки) достижима целиком по классовому протоколу — реверса не нужно, только
аккуратная реализация чтения/записи по документированным функциям.

## HyperX QuadCast S — три двери

Интерфейсы: `171D` — page 000B (телефония!) usage 05 + consumer 16/16;
`171F` — consumer, **FF90 65/65** (vendor), **FFFF in 8** (vendor, только вход).

| Дверь | Что даёт | Статус |
|---|---|---|
| Core Audio | громкость записи/мониторинга, mute, пик-метр | ✅ проверено, чтение+запись |
| Page 0x000B (Telephony) | **состояние tap-to-mute** — микрофон шлёт телефонный mute-репорт | вход 2 байта; слушать и отражать в строке |
| Page 0xFF90 (65/65) | RGB-подсветка — формат известен сообществу (OpenRGB поддерживает QuadCast S) | запись возможна по чужой документации; отдельная задача |
| Page 0xFFFF (in 8) | входные статусы (кандидат: положение ручки gain) | дослушать при активном устройстве |

**Вывод:** mute-по-касанию и живой уровень — базовая страница уже осмысленна;
подсветка — первый кандидат в «вендорский» список, но с готовой чужой
документацией (OpenRGB), т.е. дёшево.

## Flydigi APEX 5 + Charger Dock 2 — док сам всё рассказывает

Донгл пада в момент разведки был вынут (пад стоял на доке) — и это оказалось
удачей: **док вещает без запроса**, раз в ~секунду, page 0xFFA0:

```
00 5A A5 EF 08 01 00 39 00 06 00 37 00 …
      ^маркер Flydigi   ^0x39=57   ^0x37=55
```

`5A A5` — известный маркер протокола Flydigi. Два байта похожи на **два
заряда в процентах: 57% и 55%** — у CD2 два места: аккумулятор в паде на
площадке и запасной аккумулятор в слоте дока. Гипотезу подтвердит одно
наблюдение: снять пад с дока и посмотреть, какой из байтов пропадёт/замрёт
(`maxwell --desk`, раздел прослушивания).

| Дверь | Что даёт | Статус |
|---|---|---|
| Док 0xFFA0, пассивно | заряды аккумуляторов (пад на доке + запасной) | кадры пойманы; расшифровка на одно наблюдение |
| Донгл 0xFFA0? (MI_02) | статус/заряд пада в игре — протокол «Flydigi Space» | запрос-ответ, нужен реверс их приложения |
| XInput | подключение, вибротест | ✅; заряд донгл не отдаёт (врёт «wired») |

**Вывод:** заряд на строке APEX 5, когда пад стоит на зарядке — почти
бесплатный (пассивное чтение дока). Заряд в игре — вендорский реверс.

## NuPhy Air96 V2 — донгл молчит, ждёт вопросов

Донгл: обычные клав/мышь/консюмер коллекции + **page 0xFF31 usage 0x74
(65/65)** — фирменный канал. Пассивно молчит: протокол запрос-ответ.
VIA (0xFF60) через донгл не выставлен — подтверждено повторно.

| Дверь | Что даёт | Статус |
|---|---|---|
| BT-спарка | заряд из свойств Windows | доступно хоть сейчас, без кода |
| Кабель + VIA | слои, макросы, подсветка | драйвер VIA — классовый, ждёт кабеля |
| 0xFF31 (донгл) | заряд/статус по 2.4G — протокол NuPhy | реверс их софта (NuPhy Console шлёт запросы — можно подсмотреть Wireshark'ом) |

## AirPods — путь есть, эфир был пуст

Заряд живёт в BLE-рекламе Apple (company 0x004C, сообщение 0x07): проценты
обоих наушников, кейса и флаги зарядки. GATT-сервиса и Windows-свойства нет —
все «AirPods на Windows» утилиты читают именно рекламу.

Пробник готов: `maxwell --airpods`. В момент прогона эфир был пуст — реклама
идёт только с открытой крышкой кейса или наушниками в ушах. Проверка: открыть
крышку рядом с ПК и запустить пробник.

Реализация в приложении: BLE-watcher в фоне, привязка к строке по модели +
RSSI (близость). Тонкость: реклама анонимизирована ротацией MAC — привязка
эвристическая («самые близкие AirPods»), как у всех таких утилит. Честно
пометим в UI.

## Прочее, попавшее в сеть

- **AURA LED Controller (0B05:19AF)** — подсветка материнской платы ASUS,
  page 0xFF72. Не периферия стола; кандидат в каталожное `hidden`, как G HUB.
- **0145:2001 «USB Controller»** page 0001 usage 00 — аноним, уже скрыт
  правилом «неизвестный класс без каталога».

## Итого: очередь реализации по соотношению цена/польза

1. **Мышь: DPI + частота опроса** (чтение/запись, HID++ 0x2202/0x8061) — тот же
   драйвер, чистые функции.
2. **QuadCast: tap-mute в строку** (пассивный вход телефонной страницы) +
   Core Audio-страница (громкости/пик) — уже расписана в BASELINE.
3. **Док Flydigi: заряды на строке APEX 5** — пассивное чтение, одно
   подтверждающее наблюдение.
4. **AirPods: заряд из BLE-рекламы** — watcher + декодер готов в пробнике.
5. Мышь: профили 0x8100 / кнопки — под артборд 9c.
6. Вендорские с реверсом (по отдельному списку): RGB QuadCast (по OpenRGB),
   заряд Flydigi в игре, NuPhy 0xFF31.
