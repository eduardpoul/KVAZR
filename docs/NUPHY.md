# NuPhy Air96 V2: что даёт донгл, что даст кабель

Замер 27 августа 2026. Клавиатура на 2.4G-донгле, кабель не подключался.
Всё ниже — либо прочитано с этой машины, либо взято из опубликованных
исходников прошивки. Что не проверено, помечено словом «не проверено».

## Два разных устройства

| | USB id | что это |
|---|---|---|
| Донгл | `19F5:3247` | то, что видно сейчас |
| Клавиатура по кабелю | `19F5:3266` | из `keyboards/air96_v2/ansi/keyboard.json` |

Разные PID — значит по кабелю приедет **другое** устройство, со своим
дескриптором, а не тот же донгл. STM32F072, загрузчик stm32-dfu.

## Донгл: шесть коллекций

```
0001:02   вход  6                мышь: X 0x30, Y 0x31, колесо 0x38, AC Pan 0x238
0001:06   вход 16                клавиатура NKRO
0001:06   вход  9   выход 2      клавиатура обычная; выход — Caps/Num/Scroll
0001:80   вход  3                System Control: сон, пробуждение
000C:01   вход  3                Consumer: медиаклавиши
FF31:74   вход 65   выход 65     вендорский канал
```

Вендорский канал, разобранный по дескриптору:

```
input   отчёт 0x00   page FF31   usage 0x75   64 байта
output  отчёт 0x00   page FF31   usage 0x76   64 байта
feature отсутствуют
```

Отчёт с нулевым идентификатором и 64 байта в каждую сторону — форма
«вопрос-ответ», та же, что у raw HID в QMK и у разобранного публично протокола
ROYUAN. Страница другая, так что это не он.

**Канал молчит сам.** Пятьдесят секунд пассивного прослушивания двумя заходами —
ни одного кадра, при том что в те же секунды прибор ловил кнопку QuadCast и
кадры дока Flydigi. Положительный контроль есть: слушатель работает, канал
молчит. Отвечает, судя по всему, только на запрос; слов мы не знаем.

Оговорка: в обоих заходах на клавиатуре нажимались только обычные клавиши.
Шлёт ли донгл что-нибудь при смене подсветки или слоя — **не проверено**.

## Чего по донглу нет

**Заряда нет.** Ни одна из 28 HID-коллекций на этой машине не объявляет
`0x06:0x20 Battery Strength`, и ни одна не трогает страницы `0x84`/`0x85`. Все
28 дескрипторов прочитаны — не «не открылись», а прочитаны и пусты по этой
части (`--hidbattery --all` печатает счётчики кнопок и значений именно затем,
чтобы эти два случая не слипались).

**VIA не идёт.** VIA живёт на `0xFF60:0x61`, и QMK прямо пишет, что страница и
usage обязательны для связи. У донгла их нет.

## Что при этом заряд по радио ходит

В исходниках прошивки (`keyboards/air96_v2/ansi/rf.c`) обработчик
`CMD_RF_STS_SYSC` кладёт `Usart_Mgr.RXDBuf[8]` в `dev_info.rf_baterry`. То есть
радиомодуль сообщает плате заряд, и по UART он ходит.

Это участок «плата ↔ радиомодуль». Отдаёт ли донгл его дальше в USB — **не
проверено** и в открытых исходниках не описано: прошивка донгла закрыта и
обновляется отдельными файлами.

## Кабель: измерено

Переключатель сбоку — `OFF` / `WIRED` / `WIRELESS`; в проводной режим клавиатура
переходит только положением переключателя, один кабель ничего не даёт.

В проводном режиме приезжает **отдельное устройство** `19F5:3265` — не `3266`,
как в исходниках, и не донгл. Донгл при этом остаётся в системе.

```
19F5:3265  0001:02  вход  6              мышь
19F5:3265  0001:06  вход 32  выход 2     клавиатура NKRO
19F5:3265  0001:06  вход  9  выход 2     клавиатура обычная
19F5:3265  0001:80  вход  3              System Control
19F5:3265  000C:01  вход  3              Consumer
19F5:3265  FF31:74  вход 33  выход 33    вендорский (на донгле он 65)
19F5:3265  FF60:61  вход 33  выход 33    ← VIA
```

VIA отвечает:

```
версия протокола     12
слоёв                8
макросов             16, буфер 2031 байт
аптайм               идёт
параметры раскладки  0
версия прошивки      0 (не заполнена)
```

Чтение раскладки работает. Кадр ответа на `id_dynamic_keymap_get_keycode`:

```
00 04 00 00 00 00 29
│  │  │  │  │  └──┴─ код клавиши, 0x0029 = KC_ESC
│  │  │  │  └─────── колонка
│  │  │  └────────── ряд
│  │  └───────────── слой
│  └──────────────── эхо команды
└─────────────────── идентификатор отчёта
```

Ряд 1 читается как цифровой (`1E 1F 20 21 22` = 1,2,3,4,5), в ряду 0 — Esc и
коды из диапазона `0x7Exx`, то есть собственные keycode'ы NuPhy (`QK_KB_0` в
QMK равен `0x7E00`).

Команды брались из `quantum/via.h` в исходниках QMK. Разрушительные соседи —
`id_bootloader_jump = 0x0B` и `id_eeprom_reset = 0x0A` — в пробу не включены, и
список там белый, а не чёрный.

## Кабель: чего ждать

`VIA_ENABLE = yes` в `keymaps/via/rules.mk`, переопределения `RAW_USAGE_PAGE` в
`config.h` нет. Значит по кабелю ожидается стандартный `0xFF60:0x61` и с ним —
слои, раскладка, макросы и подсветка, без всякого реверса.

Ожидается, а не измерено: кабель не подключался.

## Три подключения, и как между ними переключаться

Переключатель сбоку — `OFF` / `WIRED` / `WIRELESS`. Провод работает только в положении
`WIRED`; один воткнутый кабель даёт зарядку и ничего больше.

В положении `WIRELESS` канал выбирается с клавиатуры. Позиции прочитаны из её же
раскладки по VIA, а не из руководства — печатные гиды этого семейства смешивают V1 и
V2, и одна и та же комбинация названа там и «проверить заряд», и «переключиться на
блютуз»:

```
слой 1 (Fn), ряд 1 — цифровой ряд
  колонка 1  0x7E03  Link BLE_1      Fn + 1
  колонка 2  0x7E04  Link BLE_2      Fn + 2
  колонка 3  0x7E05  Link BLE_3      Fn + 3
  колонка 4  0x7E02  Link RF         Fn + 4  — донгл
```

То же на слое 3, который маковский. `Link USB` (0x7E01) в раскладке не встречается
вовсе: проводной режим — это переключатель, а не клавиша.

Три блютуз-слота, то есть клавиатура помнит три хоста одновременно.

## Заряда нет и по кабелю

Проверено с двух сторон, уже с воткнутым проводом:

- **HID:** все 30 коллекций на машине прочитаны, из них 13 нюфаевских (6 донгла и 7
  клавиатуры). Ни одна не объявляет `0x06:0x20 Battery Strength` и ни одна не трогает
  страницы `0x84`/`0x85`.
- **VIA:** меню модели содержит только подсветку — яркость, эффект, скорость, цвет.
  Батарейной записи нет.

## А по блютузу — есть

Проверено 27 августа 2026, клавиатура сопряжена как `NuPhy Air96 V2-1`,
`bt:d86607fa8b01`:

```
NuPhy Air96 V2-1   BluetoothLe   заряд 46%   узлов 10
```

Заряд отдаёт сама Windows, тем же свойством, каким он приходит от аирподсов и от мыши
HP. Ни строчки нового кода не понадобилось — тир 0 уже это умеет.

Устройство при этом склеивается с донглом в одно: два контейнера, `bt:` и `usb:`, две
линии на странице. Подсветка на блютузе пропадает, и это верно — VIA живёт на кабеле.

### Итог по трём транспортам

| | что даёт |
|---|---|
| Донгл | имя, класс, «подключено» |
| Кабель | плюс VIA: слои, эффект, яркость, скорость, цвет |
| Блютуз | плюс заряд |

Ни один транспорт не даёт всего сразу, и это свойство железа, а не нашей работы.

### Как попасть в режим сопряжения

Переключатель в `WIRELESS`, затем **удержать Fn + 1 (2, 3) три секунды**. Короткое
нажатие только переключает на запомненный хост и стучится к нему — со стороны выглядит
как «пытается подключиться», а в эфир при этом ничего не идёт.

Три секунды — не из руководства, а из прошивки: `long_press_key()` крутится каждые
50 мс и требует `RF_LONG_PRESS_DELAY` = 60 тиков, после чего шлёт `CMD_NEW_ADV`.

## Если понадобится вскрывать донгл

Публичного разбора `0xFF31` нет — искал. NuPhyIO закрыт, только под Windows, без
SDK. Остаётся то же, чем брали Audeze: смотреть, что шлёт вендорский софт.

Слать в клавиатуру 64 байта наугад — не проба. У платы загрузчик stm32-dfu, и
неизвестный опкод может увести её туда.

## Источники

- Исходники: `GosuDRM/air96-v2`, `keyboards/air96_v2/ansi/` — форк QMK с прошивкой этой модели.
- QMK Raw HID: страница и usage обязательны, по умолчанию `0xFF60`/`0x61`.
- HID Usage Tables 1.6: `0x06:0x20` Battery Strength, 8 бит, логический максимум 100.
