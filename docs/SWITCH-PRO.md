dekuNukem/Nintendo_Switch_Reverse_Engineering; с ним согласны Linux

## Конспект протокола (то, что пойдёт в драйвер)

**Транспорты.** По Bluetooth — обычный HID, говорит сразу. По USB пад молчит,
пока не сказан handshake: `80 02`, затем `80 04` (удержать на USB-HID, иначе
через таймаут уйдёт обратно в BT).

**Кадры.** Выход `0x01`: [id, счётчик 4 бита, 8 байт румбла (нейтраль
`00 01 40 40 00 01 40 40` обязательна всегда), сабкоманда, аргументы].
Ответ `0x21`: [id, таймер, **байт 2 = батарея+линк**, кнопки(3), стики(6),
вибро, ack(бит 0x80 в [13]), эхо сабкоманды [14], данные с [15]].
Поток `0x30` (после перевода режима): то же + 3 кадра IMU по 60 Гц.

**Сабкоманды для читающего драйвера:**

| Сабкоманда | Что | 
|---|---|
| 0x02 | device info: версия прошивки, тип, MAC |
| 0x03 → 0x30 | включить полный входной режим (там батарея и IMU) |
| 0x10 | чтение SPI-флеша: адрес LE u32 + длина ≤ 0x1D |
| 0x30 | player lights (единственная «запись», полезная сразу: подсветить «какой я по счёту») |
| 0x40 / 0x48 | включить IMU / вибрацию (для вибротеста) |

**Батарея** — верхний ниббл байта 2: 8/6/4/2/0 (4 ступени) + бит зарядки.
Маппинг честный по разрешению: 100/70/40/15/5%, никакой ложной точности.

**SPI-флеш — приятное:** пад хранит **свой цвет** (0x6050: корпус RGB + кнопки
RGB) и заводскую калибровку стиков (0x603D). Цвет корпуса → можно подкрасить
строку/иконку реальным цветом конкретного пада. Серийник — 0x6000.

**Стики** — 12-бит парами в 3 байтах (декодер и тест готовы); для страницы
диагностики хватает сырых значений + калибровка из SPI.

## План драйвера (день подключения)

1. Discover по `057e:2009` (HID-энумератор уже вендор-нейтральный).
2. USB-путь: handshake → режим 0x30; BT-путь: сразу режим 0x30.
3. Capabilities: заряд+зарядка (Readout), прошивка (Readout), цвет (внутрь
   строки), player-light (Choice 1–4, первая запись — с янтарной меткой),
   вибротест (Action), диагностика стиков (живой Readout/страница).
4. Ремап на борту у Switch Pro **нет** (протокол не предусматривает) —
   честно не рисуем; программный слой — отдельное решение (см. геймпадную
   карту в CLASS-PROTOCOLS.md).
